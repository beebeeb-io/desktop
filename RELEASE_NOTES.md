# Beebeeb Desktop 0.8.23 - Windows: backups read your folders in place, stop when your files are removed, and a reinstall does not upload them again

0.8.23 changes how Windows backs up your Desktop, Documents, Pictures and other folders. Until 0.8.22 the app copied those folders into your sync folder and synced the copies. Now it reads the files where they are and uploads them into Backups › <this PC's name> in your vault. Nothing is copied into the sync folder any more. When your account's files are removed, every backup on the PC turns off and says why, instead of filling your account up again. The browser sign-in also moves to a newer version of its encryption library, which fixes a published weakness in the old one. This release is for Windows and Linux; macOS follows in a later version.

**Known limitations:**
- **Windows, the copies 0.8.22 made:** the copies the old mirror made in your sync folder (under Backups) stay on this PC as they are. This release does not free their space; that is a later step.
- **Windows, the Explorer badge:** the "Read-only" badge on Backups appears only after the sync folder is registered anew (the next sign-out and sign-in). An existing registration is kept, because registering again would remove cloud-only files from the PC.
- **Windows, a deleted removal notice:** a backup learns that your files were removed from a notice your account keeps. If that notice is deleted before a PC that was off or offline makes its next backup pass, and the backup folders are still there (for example after the files were removed when the account lapsed), that PC cannot tell, and it backs those files up again. A backup folder that was deleted still turns that backup off ("…'s backup of Pictures was deleted, so it is off."). From a server update now in progress (task 2397), the server keeps these two notices: deleting one only hides it from your list. This limitation ends when that update is live; the app needs no update for it.
- **Linux:** backups are Windows-only. The Linux app still cannot sign in: it has no support for a system password store, and its sign-in window says "This feature is not available on this device." For Linux this release changes only the core library it is built on.
- **Still as in 0.8.22:** the Windows limitations listed in 0.8.22's notes still apply (opening a large cloud-only file waits for the whole download, `robocopy` without `/J`, memory use during a download). Streaming, planned for 0.8.23 in those notes, is still switched off and moves to a later version.

### What's New

- **[Windows] Backups read your folders in place (LD-0113).**
  - Each folder you switch on in Files › Manage backup is read where it is and uploaded into Backups › <this PC's name> › <folder>. The app checks every folder every 10 minutes and about 5 seconds after something in it changes.
  - Backups are one way. A file you delete on this PC stays in the backup. A file someone deletes from the backup elsewhere stays deleted until it changes on this PC.
  - If you already used backup in 0.8.22, the app finds the folder the old mirror filled and keeps using it.
  - If OneDrive has moved one of these folders, the app asks once which one to back up, OneDrive's folder or the default one, and backs up nothing from that folder until you answer. After backing up OneDrive's folder, it says how many files were online-only in OneDrive and were not backed up; it never downloads them.
- **[Windows] A backup stops, and says why, when your files are removed (LD-0121, LD-0139).**
  - Before each backup pass the app reads every notice of your account about removed files or deleted backups since that folder's last pass, page by page. When your files have been removed (Erase all files, the account lapsing, the inactive-account cleanup or an account reset), every backup on this PC turns off at its next pass, even where its folders are still there, and the Backups card says why, for example "Your files were erased, so backups are off.", with a "Back up again" button. A backup never fills your account up again by itself.
  - A backup folder deleted from another device says "<PC name>'s backup of Pictures was deleted from another device."; a folder that is gone with no notice says "<PC name>'s backup of Pictures was deleted, so it is off."
  - A notice the server was still writing while the previous pass read the notices still counts at the next pass: each pass reads 10 minutes further back than its last pass. The app remembers which notices each backup already acted on, so "Back up again" is never undone by the notice that stopped the backup.
  - "Back up again" starts that folder again from that moment: what is already in your vault counts as backed up, so nothing is uploaded twice.
  - If the app cannot read every notice (a server or network error on any page), it uploads nothing in that pass, says "Couldn't check — will retry." and tries again at the next pass. The same happens when it cannot read which backups are turned off on this PC.
  - After this update: 0.8.22 kept no record of when it last backed up, so a backup that was already on counts every earlier removal of your files. If your account's files were ever removed before, those backups turn off at their first pass and offer "Back up again", one click. A folder you turn on after the update starts from the moment you turn it on.
- **[Windows] Backups are read-only in Explorer (LD-0113).** Files under Backups cannot be changed, deleted, renamed or moved there from Explorer; the app keeps the backup up to date from the original folders. Each PC's hidden `.device.json` is never shown.
- **[Windows] A reinstall does not upload your backups again (LD-0139).** When this PC has no record of what it backed up (a reinstall, or the first pass into the old mirror's folder), the app rebuilds that record from what is already in your vault: a file counts as backed up when its copy was made after the file last changed. The app now measures how far this PC's clock is from the server's, from the time the server sends with every answer, so a copy made seconds after a change counts. Without the measurement, any copy made within 10 minutes of its file's last change would be uploaded again. A copy made within about 2 seconds (plus the time one request takes) of the change is uploaded again, which is the safe direction.

### Bug Fixes / Hardening

- **[Windows, Linux] The browser sign-in uses core's key exchange, on p256 0.14 (LD-0139, RUSTSEC-2026-0387).** The app's own copy of the sign-in's key exchange ran on the `p256` 0.13 library, whose arithmetic has secret-dependent branches (advisory RUSTSEC-2026-0387). The app now uses the same code as the `bb` CLI, from beebeeb-core, on `p256` 0.14. What goes over the wire is byte-for-byte the same: a test checks the app's public key, its decryption of the current and the legacy (v0.4) browser format, and a compressed browser key against core's published vectors. A browser answer with a malformed nonce is now an error message; the old copy crashed the sign-in on it.
- **[Windows] A backup that turned off stays off.** A stop is recorded in one step together with the notice it acted on, so a crash in the middle neither loses the stop nor applies it twice. If the app is closed before it switches the folder off in Settings (or that settings write fails), the switch is turned off when the app starts and before every pass. Verified by tests that abort the write halfway at each of its two tables, and by tests that find a stopped folder's switch still on.
- **[Windows, Linux] Built on beebeeb-core v0.2.5** (https://github.com/beebeeb-io/core/releases/tag/v0.2.5). 0.8.22 was built on core v0.2.0. v0.2.1 to v0.2.5 add the backup rules this release uses, the clock rule above, the check that stops a backup with its 10-minute margin and the notices it remembers, the p256 update, and `zip` 9.4.1 (RUSTSEC-2026-0429, -0367, -0368 and -0369; core's notes say none of the four was reachable from core's own code).

### Install / Update

This release is published to the alpha channel first. Windows installs following that channel receive it through the in-app updater; stable installs receive it only once it is promoted to stable.

macOS: not in this release; it follows in a later version.

For a fresh Windows install, download the NSIS `setup.exe` from the GitHub release assets.
