The three Settings dialogs, drawn

Choose folders, Repair and Sign out were built in slice 4 on the shared Modal and never drawn. This page renders them exactly as built, in the Settings-window visual language, and reflects the shipped state: the Sign out confirm button is destructive red (ms-btn--danger, PR #104), and Return triggers the focused confirm button.

These dialogs follow existing Modal styling — do we accept that, or want their own dialog treatment before slice 6 flips the window on?Decision file question 1 · 1683-s4-undrawn-and-unbacked

All three are acceptable as built. The Modal anatomy is right for a Settings window: title, close button, body, footer, Esc to dismiss. Nothing needs its own window chrome. One recommended follow-up, no blockers for slice 6.

1 · Sign out — confirmation

Opened from the Account tab row “Sign out of this Mac” by the Sign out… button. Drawn twice: the shipped destructive treatment (PR #104), and the pre-#104 amber treatment kept for comparison. Both use the same copy.

2 · Repair Beebeeb in Finder — confirmation

Opened from the Sync tab when the Finder row reports added, via the Repair… button. The confirm button stays amber: repair removes the Finder location but is reversible (“You can add it back afterwards”), so it is a caution, not a destruction. While it runs, the trigger button reads Repairing… and the dialog is already dismissed. Amended 6 Oct 2026 (ruling R5): Repair now adds Beebeeb back to Finder by itself, so it is still a caution, not a destruction.

3 · Keep on this Mac — folder list

Opened from the Sync tab row “Keep on this Mac” by the Choose folders… button. This is a settings sheet: changes save the moment a switch flips; there is no footer except the default Close. Drawn with three example folders, one with a path hint, one disabled while its save is in flight.

4 · Switch to a different account — confirmation

Added 6 Oct 2026 (ruling R8, docs/specs/2026-10-06-macos-finder-setup-reconciler.md). Shown when a sign-in is a different account from the one on this Mac. The same account never sees it: only its session token is replaced, and Finder, keys, cache and pending edits stay. Cancel changes nothing. The confirm button is destructive: it signs the other account out of this Mac and removes changes that have not uploaded.
