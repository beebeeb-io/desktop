The three Settings dialogs, drawn

Choose folders, Repair and Sign out were built in slice 4 on the shared Modal and never drawn. This page renders them exactly as built, in the Settings-window visual language, and reflects the shipped state: the Sign out confirm button is destructive red (ms-btn--danger, PR #104), and Return triggers the focused confirm button.

These dialogs follow existing Modal styling — do we accept that, or want their own dialog treatment before slice 6 flips the window on?Decision file question 1 · 1683-s4-undrawn-and-unbacked

Verdict per dialog (question 1)

All three are acceptable as built. The Modal anatomy is right for a Settings window: title, close button, body, footer, Esc to dismiss. Nothing needs its own window chrome. One recommended follow-up, no blockers for slice 6.

1 · Sign out — confirmation

Opened from the Account tab row “Sign out of this Mac” by the Sign out… button. Drawn twice: the shipped destructive treatment (PR #104), and the pre-#104 amber treatment kept for comparison. Both use the same copy.

Amended 11 Oct 2026 (task 1887, docs/specs/2026-10-10-macos-sign-out-waiting-writes.md). Sign out in this sheet first counts what waits. Nothing waits: the sign-out runs, as drawn above. Changes wait and the app can send: the sheet becomes the send phase. Changes still wait, or none could be sent: the ask. Closing Settings at the count, the send phase or the ask ends the flow with nothing changed. After a sign-out that kept files: one alert, drawn by macOS. The send phase is drawn at the Modal’s 400, the ask at 440 (as Choose folders). Counts and paths are examples.

2 · Repair Beebeeb in Finder — confirmation

Opened from the Sync tab when the Finder row reports added, via the Repair… button. The confirm button stays amber: repair removes the Finder location but is reversible (“You can add it back afterwards”), so it is a caution, not a destruction. While it runs, the trigger button reads Repairing… and the dialog is already dismissed. Amended 6 Oct 2026 (ruling R5): Repair now adds Beebeeb back to Finder by itself, so it is still a caution, not a destruction.

3 · Keep on this Mac — folder list

Opened from the Sync tab row “Keep on this Mac” by the Choose folders… button. This is a settings sheet: changes save the moment a switch flips; there is no footer except the default Close. Drawn with three example folders, one with a path hint, one disabled while its save is in flight.

4 · Switch to a different account — confirmation

Added 6 Oct 2026 (ruling R8, docs/specs/2026-10-06-macos-finder-setup-reconciler.md). Shown when a sign-in is a different account from the one on this Mac. The same account never sees it: only its session token is replaced, and Finder, keys, cache and pending edits stay. Cancel changes nothing. The confirm button is destructive: it signs the other account out of this Mac and removes changes that have not uploaded. Amended 11 Oct 2026 (task 1887): on macOS it first copies each file whose changes haven’t reached the server, and that still has Beebeeb’s copy, to a folder on this Mac and shows where; the other changes (renames, moves, deletions, new folders, restores) are dropped, and so is a change whose copy is missing.

Amended 6 Oct 2026 — the warning lives in the onboarding window. A sign-in that is a different account only ever happens in the onboarding window (“Sign in again” opens it in place), so a Settings-style Modal can never appear in this flow. The surface is a Card step with the same copy, drawn first below; the Modal drawing under it is kept for the record and is superseded as to surface. Differences from the Modal: no close × (Cancel is the way out: it closes the sign-in window, or goes back to the sign-in form when set-up is running); the confirm is the filled destructive button (the 1683 dialog ruling: --red fill, fixed --red-ink label, as ms-btn--danger), never the amber primary; and on open, focus is on Cancel, so Enter cancels and can never confirm. — lead, 2026-10-06 (execution ruling: the warning lives in the onboarding window; Card variant, same copy, destructive confirm, focus on Cancel)

Replaced 11 Oct 2026 (task 1887). Until then both changes-waiting drawings read “This Mac is signed in to another Beebeeb account, and 3 changes on this Mac haven’t uploaded yet. Switching signs that account out of this Mac and removes them.”, and their captions said one change reads “1 change … hasn’t uploaded yet … removes it.” On macOS the switch now copies waiting files to a folder on this Mac first (spec 2026-10-10, A2s). Linux keeps that copy: its sign-out still removes those changes (spec 2026-10-10 §10).

Original drawing, 6 Oct 2026 — the Settings-style Modal, kept as first drawn (copy identical; superseded as to surface by the Card variant above). Amended 11 Oct 2026 (task 1887): its changes-waiting copy follows the Card’s.

5 · Settings › Backup — folders backed up from where they are

Added 6 Nov 2026 (LD-0113, design for review). Spec docs/superpowers/specs/2026-11-06-backup-from-source-design.md §6.1 and §6.5 in the workspace, plan Task D5 step 2 and Amendment 1 item 6. A Mac backs up Desktop, Documents, Pictures, Music, Videos and Downloads straight from where they are: nothing is copied into the Beebeeb folder, and what is backed up is in the drive as cloud-only files, never kept on this Mac. Each folder needs a grant once. macOS lets Beebeeb read a folder only after the person chooses it in a folder picker, and the grant is kept, so it is asked once per folder.

Drawn as the Beebeeb window at its default 920 × 620 pt, in the System Settings style of design/hifi/macos-two-surface.html §4. Backup is a new section in the Settings sidebar, after Sync. The pane is the shipped .ms- card and rows, the controls are this page’s own (neutral ink switch, amber only on the primary button), and only the pane scrolls. All four states fit in 620 pt without scrolling. Switches are live in this mockup. Names, counts and paths are invented examples.

Decisions (lane, 6 Nov 2026) — each one is open for Guus’s review of this drawing, and each changes here before any code does.

  • Backup is a sixth Settings section, between Sync and Security, because the spec names it “Settings › Backup” (§6.4 point 5). Six rows and their lines in Sync would push Speed below the window’s edge. This amends the two-surface spec’s “the sections are the five asked for” (§7.8). Like Sync and Security, it is shown only while signed in.
  • On a Mac the NotLocal line names iCloud: “N files are only in iCloud and were not backed up”. Windows names OneDrive (spec §6.5). Within these six folders, the files macOS keeps only in the cloud are iCloud Drive’s (Desktop and Documents in iCloud, and older .icloud placeholders; spec §4.2 rule 8).
  • One switch per folder, and a grant slot under its name. Before the grant, the slot is “Choose folder…”. After it, the slot holds the chosen path, in mono, never cut off (task 1882 I2). Turning the switch on without a grant opens the same picker. The status sits at the right, before the switch, as Sync’s “3 folders” sits before its button.
  • Skip lines live in the row of the folder they count, under its path, and a line at 0 is left out. The singular forms (copy table) follow the spec’s plural lines.
  • “Deleted from another device” is a status note under that folder’s row (the shipped .ms-note), not an alert, because nothing failed on this Mac. The folder shows off, and its grant stays. Turning the switch on does the same as “Back up again”, so the switch and the note never disagree.
  • The one-way promise is the Windows card’s sentence, word for word, as the footnote under the card, so both platforms make the same promise in the same words.
  • The Videos row is named by core’s category, “Videos”, which is also the name of its folder in the drive. On a Mac its picker opens at ~/Movies, and its path shows that (spec §4.1: ~/Movies maps to Videos).
  • The switches stay neutral ink, as every switch on this page. Amber appears once, on “Back up again”, the pane’s one primary action.
  • The Backup section’s tile is an archive box, a new archive entry in SettingsIcon, on the 24-unit grid and in the line weight of the others.

Open for Guus — drawn as the spec writes it, with a proposal beside it:

  • A Mac’s default name already ends in a possessive, so the deleted line reads “Sam’s MacBook Pro’s backup of Pictures…”. Drawn verbatim. A proposal for the Mac only: “This Mac’s backup of Pictures was deleted from another device”.
  • When the whole device folder is deleted, every folder that was on turns off. Drawn here for one folder: is it one note per folder, each with its own button, or one line and one button for all?
  • The folder picker is drawn by macOS, and its words are ours to set. Proposal: the message “Choose the folder to back up as Pictures.” and the button “Choose”. A person may choose a different folder than the one it opens at: the slot then shows that path, and the backup is still named Pictures.
  • “Videos” or “Movies” for that row on a Mac (Decision above: “Videos”).

Not drawn here: a grant that no longer opens (the folder was moved or renamed, or its disk is not connected); the pane while sync is paused, which pauses backup too; a switch that did not save (a toast, as Keep on this Mac’s); the dark theme, which the button at the top right switches. This is a browser render: nothing here has run in the real window on a Mac.
